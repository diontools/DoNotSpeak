# 通知設定と実動作の整合対応

## 背景

Android 13以降の設定画面にある「通知を使用する」は、`USE_NOTIFICATION`へ通知権限を要求する
意向を保存するが、通知表示そのものは制御しない。無効にしてもOS権限や通知チャンネルは変わらず、
フォアグラウンドサービスはAndroidの要件に従ってステータス通知を作成するため、表示名と実動作が
一致していなかった。

## 目標

- 通知のアプリ内ON/OFFと誤認されるチェックボックスを廃止する
- アプリ通知、ステータス通知チャンネル、復旧通知チャンネルの実状態を表示する
- 未許可時は権限要求、許可済みの場合はOSの通知設定へ遷移できるようにする
- 通知権限にかかわらずフォアグラウンドサービスの通知生成契約を維持する

## 対象外

- アプリから`POST_NOTIFICATIONS`を取り消す処理
- 通知権限拒否時にステータス通知の生成を省略する処理
- `MainActivity`の起動時権限要求フローの変更
- AUD-001で扱うフォアグラウンドサービス起動失敗時の復旧処理

## 対応方針

- `USE_NOTIFICATION`は起動時に通知権限を要求する意向を保持する内部値として維持する
- Android 13以降の設定画面では`NotificationManager.areNotificationsEnabled()`と各チャンネルの
  `importance`を読み取り、保存値ではなくOSの実状態を表示する
- 通知権限が未許可なら「通知を許可する」、許可済みなら「通知設定を開く」を表示する
- `DNSService`はAPI 28以降でアプリ通知と通知チャンネルのブロック状態変更Broadcastを受信し、
  ステータス通知が表示可能になった時点で現在状態の通知を再発行する
- `SettingActivity.onResume()`ではOSの実状態を再取得して表示だけを更新する
- 通知設定画面には`Settings.ACTION_APP_NOTIFICATION_SETTINGS`で遷移する
- 通知再発行では`ACTION_APPLY_SETTINGS`を使用せず、保存設定の再読込や音量制御を行わない

## 実装結果

- 「通知を使用する」チェックボックスを通知状態表示と操作ボタンへ置き換えた
- アプリ通知と2つの通知チャンネルを、有効、無効、未作成、取得不能に区別して表示する
- 明示操作による権限再要求とOS通知設定への遷移を追加した
- `DNSService`が通知ブロック状態変更Broadcastを受信し、ステータス通知が表示可能になった時点で
  `createNotification()`を直接呼び出して通知を再発行する
- `SettingActivity.onResume()`は通知状態表示の更新だけを行い、`ACTION_APPLY_SETTINGS`は送信しない
- `USE_NOTIFICATION`と`MainActivity`の権限要求・サービス開始順序は変更していない

## 検証計画

- Debug APKをビルドする
- androidTestをコンパイルする
- Lintで変更ファイルへの新規指摘がないことを確認する
- API 36で日本語と英語、ライトテーマとダークテーマの設定画面を比較する
- 通知権限の許可、拒否、各通知チャンネル無効化後に表示とボタン動作を確認する
- 通知権限拒否中もフォアグラウンドサービスが動作することを確認する

## 検証結果

- `assembleDebug`成功
- `compileDebugAndroidTestJavaWithJavac`成功
- `lintDebug`は既存箇所の8 errors / 33 warningsで失敗したが、AUD-004の変更ファイルへの指摘はない
- 2026-08-22にOS設定で通知を有効化して戻った際、既存のForeground Service通知が自動表示
  されないことを確認した
- 設定画面復帰時の再適用ではなく、通知ブロック状態変更Broadcastの受信時に通知を再発行するよう修正した
- Broadcast対応後も`assembleDebug`と`compileDebugAndroidTestJavaWithJavac`が成功した
- Broadcast対応後の`lintDebug`も既存箇所の8 errors / 33 warningsで失敗し、追加箇所への新規指摘はない
- 2026-08-22のAPI 36検証で、日本語・英語およびライト・ダークテーマの設定画面に
  レイアウト崩れがないことを確認した
- 通知権限の許可・拒否と各通知チャンネルの状態が設定画面へ反映され、権限要求と
  OSの通知設定への遷移が動作することを確認した
- アプリ通知またはステータス通知チャンネルを有効化した際に、稼働中のサービスが
  ステータス通知を再表示することを確認した
- 通知権限を拒否した状態でもForeground Serviceが継続することを確認した
- 修正コミット: `6974177`
- 確認日: 2026-08-22

## 完了条件

- API 36のスクリーンショットでレイアウト崩れがない
- 通知権限とチャンネル状態が設定画面へ正しく反映される
- 権限要求と通知設定への遷移が動作する
- アプリ通知またはステータス通知チャンネルを有効化した時点で通知が再表示される
- 通知権限拒否中もサービスが継続する
- 問題一覧と現行仕様を検証結果に合わせて対応済みへ更新する
