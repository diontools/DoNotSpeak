# プロジェクト調査結果

調査日: 2026/07/26
対象: `dev` ブランチ / `5fb73ad`

## 概要

ソースコード、Android ビルド、Lint、テスト構成、Google Play 発行スクリプト、
GitHub Actions、公開されている既知 Issue を調査した。

優先して対応すべき問題は次のとおり。

1. 音量変更 API の `SecurityException` による既知クラッシュ
2. Foreground Service 起動時の未処理例外による既知クラッシュ
3. Exported Activity を経由した他アプリからの状態変更
4. 「通知を使用する」設定と実際の動作の不一致
5. 定期アラームの初回発火時刻の誤り

## 問題

### 1. 音量変更時の既知クラッシュ

重要度: 高

対応状況: 対応済み（2026/07/27）

`DNSService.setVolumeTo()` の音量取得・変更処理全体で `SecurityException` を捕捉し、
診断ログへ記録してサービスを継続するようにした。例外発生時はユーザーへ短い Toast で案内する。
段階調整中に例外が発生した場合も、再入防止フラグは `finally` で解除される。

調査時点の `DNSService.setVolumeTo()` は次の API が投げる `SecurityException` を処理していなかった。

- `AudioManager.adjustStreamVolume()`
- `AudioManager.setStreamVolume()`

対象:

- `src/app/src/main/java/io/github/diontools/donotspeak/DNSService.java:660`
- `src/app/src/main/java/io/github/diontools/donotspeak/DNSService.java:681`
- `src/app/src/main/java/io/github/diontools/donotspeak/DNSService.java:684`
- `src/app/src/main/java/io/github/diontools/donotspeak/DNSService.java:694`

Android の仕様では、音量変更によって Do Not Disturb の状態が変わり、アプリに通知ポリシーへの
アクセス権がない場合、これらの API は `SecurityException` を投げる。

公開されている Issue #31 には、Galaxy S24 / Android 14 で
`setStreamVolume()` からこの例外が発生したスタックトレースが記録されている。調査時点では
例外処理がなかったため、同じ条件でサービスを含むアプリプロセスが終了する可能性があった。

参考:

- [Issue #31 の Galaxy S24 クラッシュ記録](https://github.com/diontools/DoNotSpeak/issues/31#issuecomment-2408819644)
- [AudioManager API](https://developer.android.com/reference/android/media/AudioManager)

対応案:

- 音量の取得・変更処理全体で `SecurityException` を捕捉する
- 例外を診断ログへ記録し、サービスを終了させない
- 必要なら `NotificationManager.isNotificationPolicyAccessGranted()` を確認し、ユーザーへ案内する
- `setStreamVolume` と `adjustStreamVolume` の両経路をテストする

### 2. Foreground Service 起動失敗が未処理

重要度: 高

次の Foreground Service 起動処理には例外処理がない。

- `src/app/src/main/java/io/github/diontools/donotspeak/Compat.java:23`
- `src/app/src/main/java/io/github/diontools/donotspeak/Compat.java:25`
- `src/app/src/main/java/io/github/diontools/donotspeak/DNSService.java:619`

Android 12 以降では、バックグラウンドから Foreground Service を開始または Foreground へ
昇格できない場合、`ForegroundServiceStartNotAllowedException` が発生する。

Issue #31 には Android 13 の Samsung、Sony、Xiaomi 端末で、この例外によってクラッシュした
記録がある。`BOOT_COMPLETED` と `MY_PACKAGE_REPLACED` は通常の Android ではバックグラウンド
起動制限の例外だが、実端末での失敗が記録されているため、例外処理は必要である。

参考:

- [Issue #31](https://github.com/diontools/DoNotSpeak/issues/31)
- [Foreground Service の起動制限](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)
- [Foreground Service の起動方法](https://developer.android.com/develop/background-work/services/fgs/launch)

対応案:

- `Context.startForegroundService()` と `Service.startForeground()` の両方で例外を処理する
- 起動できなかった場合はサービス状態を破棄せず、再起動通知などへフォールバックする
- Boot、パッケージ更新、通知操作、Activity 操作の各起動経路を個別にテストする

### 3. 他アプリから保護状態を変更できる

重要度: 中

`MainActivity` はランチャー Activity として `android:exported="true"` になっている。

対象:

- `src/app/src/main/AndroidManifest.xml:33`
- `src/app/src/main/java/io/github/diontools/donotspeak/MainActivity.java:225`
- `src/app/src/main/java/io/github/diontools/donotspeak/MainActivity.java:229`

Exported Activity は他アプリから正確なクラス名を指定して起動できる。`MainActivity` は呼び出し元を
確認せず、受け取った Action に応じて次の状態変更を実行する。

- `STOP_UNTIL_SCREEN_OFF`: 画面消灯までミュート保護を解除
- `SWITCH`: ミュート状態を切り替え
- `SHUTDOWN`: 停止確認ダイアログを表示

Action 名をパッケージ固有に変更するだけでは、明示的 Intent による呼び出しは防げない。

参考:

- [android:exported のセキュリティ解説](https://developer.android.com/privacy-and-security/risks/android-exported)

対応案:

- 外部公開するランチャー入口と、内部の状態変更処理を分離する
- 外部から呼び出せる経路では、状態を変更する前にユーザー確認を必須にする
- 通知などアプリが生成した経路では immutable な `PendingIntent` を使用する

### 4. 「通知を使用する」設定が通知を無効化しない

重要度: 中

`SettingActivity` は `USE_NOTIFICATION` を保存するが、`DNSService.applySettings()` はこの設定を
読み込まない。Foreground Service の通知は常に作成される。

対象:

- `src/app/src/main/java/io/github/diontools/donotspeak/SettingActivity.java:120`
- `src/app/src/main/java/io/github/diontools/donotspeak/DNSService.java:369`
- `src/app/src/main/java/io/github/diontools/donotspeak/DNSService.java:591`
- `src/app/src/main/java/io/github/diontools/donotspeak/DNSService.java:619`

通知権限を一度許可した後にチェックを外しても、権限は取り消されず、通知も引き続き表示される。
現在のチェックボックスは、実質的には今後の通知権限要求を抑止するだけである。

Foreground Service 自体には通知が必須なため、サービスを継続したまま通知を完全に作成しない実装には
できない。

参考:

- [Android の通知ランタイム権限](https://developer.android.com/develop/ui/compose/notifications/notification-permission)

対応案:

- 設定名と説明を「通知権限を使用する」など、実際の動作に合わせる
- 無効化時はアプリの通知設定画面へ誘導する
- アプリ内設定と実際の `POST_NOTIFICATIONS` 許可状態を区別して表示する

### 5. 定期アラームの開始時刻が絶対値になっている

重要度: 低

対象:

- `src/app/src/main/java/io/github/diontools/donotspeak/DNSService.java:537`
- `src/app/src/main/java/io/github/diontools/donotspeak/DNSService.java:540`

現在の処理:

```java
alarmManager.setInexactRepeating(
        AlarmManager.ELAPSED_REALTIME,
        60 * 60 * 1000,
        60 * 60 * 1000,
        rebootIntent);
```

`ELAPSED_REALTIME` の `triggerAtMillis` は「現在からの待ち時間」ではなく、端末起動からの絶対時刻である。
端末起動から1時間以上経過している場合、過去の時刻を指定することになり、アラームが即時発火する。
サービスコマンドのたびに同じアラームを再設定するため、不要な Broadcast が発生する。

参考:

- [AlarmManager API](https://developer.android.com/reference/android/app/AlarmManager)

対応案:

```java
long interval = AlarmManager.INTERVAL_HOUR;
long firstTrigger = SystemClock.elapsedRealtime() + interval;
alarmManager.setInexactRepeating(
        AlarmManager.ELAPSED_REALTIME,
        firstTrigger,
        interval,
        rebootIntent);
```
