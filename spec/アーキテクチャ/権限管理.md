# 権限管理

## 宣言権限

| 権限 | 対象 | 用途 |
| --- | --- | --- |
| `RECEIVE_BOOT_COMPLETED` | 全対応API | 端末起動後のサービス開始 |
| `FOREGROUND_SERVICE` | Android 9以降 | フォアグラウンドサービス |
| `FOREGROUND_SERVICE_SPECIAL_USE` | Android 14以降 | 音量・接続監視のspecialUse FGS |
| `BLUETOOTH` | Android 11以前 | Bluetooth状態取得 |
| `BLUETOOTH_CONNECT` | Android 12以降 | 接続機器の取得 |
| `POST_NOTIFICATIONS` | Android 13以降 | ステータス通知と復旧通知 |
| `WAKE_LOCK` | 全対応API | 一時停止中の画面維持 |

## 実行時権限

ランチャー起動時はBluetooth権限、続いて通知権限を確認し、完了後にサービスを開始する。
設定画面で機能を有効にした場合も必要な権限を確認する。

Bluetooth利用設定はユーザーの選択、OS権限は実行時に利用可能かを表す別々の状態として扱う。
`DNSService.applySettings()`は保存設定の読込だけを行い、実権限によって設定値を書き換えない。
Bluetoothを実際に利用する箇所では`DNSService.canUseBluetooth()`によって設定値と実権限を
組み合わせる。

権限結果は次のように扱う。

- 許可: 対応機能を有効にする
- 拒否: Bluetooth判定を実行せず、Bluetooth機器を非接続として扱う
- キャンセルまたは設定画面へ移動: サービスの利用箇所で現在の実権限を確認する

Bluetooth権限がない場合、サービスはBluetoothプロファイルの初期化を待たずに処理を継続する。
その際は`BLUETOOTH_CONNECT permission: denied`を診断ログへ記録し、設定無効およびプロファイル
初期化待ちのログと区別する。Android 12以降の実機検証は
[AUD-003](../問題管理/問題一覧.md#aud-003-bluetooth権限不足時に初期化を待ち続ける)で管理する。

## コンポーネント公開

外部公開するコンポーネントは、公開理由と許可する操作を明示する。ランチャーActivityを通じた内部状態変更を
外部呼び出しへ公開しない。現行の未達事項は
[AUD-002](../問題管理/問題一覧.md#aud-002-外部公開activityから状態を変更できる)で管理する。
