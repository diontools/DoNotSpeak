# テスト方針

## 変更ごとの基本確認

Androidコード変更では、影響に応じて次を実行する。

1. Debug APKビルド
2. androidTestのコンパイル
3. Android Lint
4. API 21でのインストール確認
5. 影響対象APIでの機能確認
6. UI変更時のスクリーンショット比較

スクリプト変更ではTypeScript型チェックを実行する。依存関係変更時はnpm監査も行う。

## 自動テスト

現在のandroidTestは次を提供する。

- `SmokeTest`: instrumentation、shell command、スクリーンショット保存の疎通確認
- `ScreenshotTest`: 主要画面のスクリーンショット取得
- `BluetoothPermissionServiceTest`: Bluetooth設定と実OS権限の組み合わせ、初期化非待機、安全側の音量0を検証
- `BluetoothPermissionFlowTest`: Bluetooth権限説明ダイアログのキャンセルからService開始までをE2Eで検証

Bluetooth権限試験はAPI 31またはAPI 36の起動済みエミュレータに対し、リポジトリルートから
serialを明示して実行する。

```sh
scripts/android/run-bluetooth-permission-tests.sh emulator-5554
```

スクリプトは各instrumentation実行前に対象アプリを停止・初期化し、`BLUETOOTH_CONNECT`の
拒否または許可をADBで設定する。拒否、設定無効、ダイアログキャンセル、許可をJUnitの実行順へ
依存せず個別に実行し、結果とLogcatを`src/build/reports/bluetooth-permission-tests/`へ保存する。

サービス全体の状態、例外経路を検証するUnit Testは存在しない。この不足は
[AUD-008](../問題管理/問題一覧.md#aud-008-サービスの自動テストが不足している)で管理する。

## CI

`android-emulator-tests.yml`はAPI 31とAPI 36をmatrix実行し、Bluetooth権限androidTestを実行する。
エミュレータActionはrelease commit SHAへ固定し、失敗時もinstrumentation結果とLogcatをartifactへ保存する。
テストコミット`3f98cf8`のGitHub Actions run [31940795652](https://github.com/diontools/DoNotSpeak/actions/runs/31940795652)で、
API 31・36の両ジョブと診断artifact保存が成功した。

`android-build-check.yml`はpull request、`master`・`dev`へのpush、手動実行で
`lintDebug assembleDebug`を実行する。署名シークレットとレポートartifactは使用せず、Lintエラーは
Gradleの終了コードでDebugビルド検証を失敗させる。警告は成功を許可し、baseline、全体抑止、
`abortOnError = false`は使用しない。

2026-08-22にコミット`ca84f8b`で確認した8 errors / 33 warningsのうち、AUD-007の修正後は
0 errors / 33 warningsとなった。33件の警告整理は
[AUD-009](../問題管理/問題一覧.md#aud-009-lint警告が未整理)および
[対応計画](../対応計画/AUD-009_Lint警告整理.md)で管理する。実装コミット`9914846`の`dev`へのpushで
[Android Build Check run 32567063064](https://github.com/diontools/DoNotSpeak/actions/runs/32567063064)が起動し、
GitHub Actions上でも`lintDebug assembleDebug`が成功した。一時PR
[#45](https://github.com/diontools/DoNotSpeak/pull/45)の
[run 32568469636](https://github.com/diontools/DoNotSpeak/actions/runs/32568469636)では、意図的な
`NewApi`エラーを検出して`:app:lintDebug`が終了コード1で失敗することも確認した。

release workflowはbundleのビルドを中心とし、Unit TestとTypeScript型チェックは品質ゲートとして
実行していない。

## 画面確認

UI変更は[スクリーンショットテスト](スクリーンショットテスト.md)に従い、API、ロケール、
ナビゲーション、テーマの必要な組み合わせを比較する。
